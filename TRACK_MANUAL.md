# ETK TRACK MANUAL — draft v0.1 (2026-07-11)

This is the working system manual for the **Emulation Tuning Kit (ETK / GTK Edition)** — the single document that bootstraps every working session. It condenses the README, `AI_MANIFEST.md`, the dossier archive, and six weeks of session memory into one map: the mission, the machinery, the forensic method, and the live frontier. Where a claim is load-bearing it carries its evidence (date, N, commit, or dossier). `AI_MANIFEST.md` remains the deep technical reference (BusyBox laws, SHM map, sway/mako gotchas); this manual is the cockpit view.

## 1. THE MISSION & THE KPI

**Mission:** specialize ONE SM8250 handheld (Retroid Pocket Flip 2) to run the PS3 Gran Turismo series at race stability approaching console quality — RPCS3 + Mesa Turnip on ROCKNIX, with the **whole stack fair game**: kernel, video driver, emulator, middleware, OS image (`dossiers/MissionBrief.md`). It is research with an honest-outcome clause: if a ceiling is truly unmovable, the deliverable is a reasoned account of the SM8250 class limits. Current verdict: **silicon is not the wall** — every crash class mapped to fixable software; the true adversary is non-determinism, treated as an instrument-calibration problem, not a defect.

**THE KPI — Fable's Challenge (operator-set 2026-07-04):** locked **60 FPS / 16.7 ms at NATIVE 720p (res 100)** = console quality. Judged by **PERFECT-window share** (`perfect_pct`, ledger col 29), never fps averages. Resolution-lowering = cheating. The crash-net is the **tax** that makes racing for the KPI free — it is not the mission. Per-title lock targets (never compare across titles): GT HD = locked-60, frametime [15.5, 18.0] ms; GT5P family (NPEA00050 / NPUA80075 / NPEA00502) = locked-30, [31.0, 36.0] ms. We are assuming this headroom unlocks stutter-free race audio.

**Roles — the Garage-to-Car model:** Claude = **Engineer** (preps, arms, analyzes, builds); operator = **Driver** (physically at the rig: reboots on-device, runs `install.sh`, presses R3, races events competitively, achieves game progress, gives the feel verdict). *Verdict from the operator's screen, mechanism from the log.*

**Client orientation (2026-07-03):** the kit has real users now: Our A/B Android forks have garnered downloads, but ROCKNIX-GTK adoption is a higher bar to still achieve. Expertise ships **as defaults** (anti-lock, flicker fix, golden dial values — all default-ON, kill-switchable); user surfaces get plain language and fail-soft behavior ("it still plays"); jargon stays in dossiers/AI_MANIFEST.

## 3. SESSION PROTOCOL (start here, every session)

1. **Read this manual**, then consult `AI_MANIFEST.md` for any law you're about to lean on (some manifest laws were later falsified — verify before building on one). 2. **`git status` scope-check:** uncommitted/untracked files may be parked experiments (e.g. `manual_forensics/`, pad-movie B-fork). When task and diff diverge, ask which files are in scope before absorbing them. 3. **Non-negotiables:** - **Always-reboot gate** — every tune/config change must survive a COLD boot; `/storage` persists, nothing else does. - **Use the kit — including skill automation.** Prefer ETK tools (install/uninstall, Pitstop, `etk_telemetry`, `recovery.sh`) and the **cockpit skill's own loops** over hand-rolled ssh surgery. Concrete miss to never repeat (2026-06-18): hand-rolled per-freeze grim grabs while `rocknix_spotter_loop.sh` — a purpose-built crash-watch — sat unused. - **Law #7, HARNESS vs TOOLING:** disposable on-rig state is licensed for tuning **values** only. Any script that watches/measures/toggles/captures is a **tool** and enters through the kit (repo + install.sh push list + an existing surface) from its first run. A `/tmp` hand-push died to two cold boots and was re-pushed three times on 2026-07-10 before this became law. "If a temporary script is worth running twice, it is a tool." - **Validate before integrate** — prove speculative tuning on a disposable harness, cold-booted, before touching locked-down core (install.sh, daemons, ledger schema, the R3 panic path). - **NEVER reboot the rig remotely; the operator runs install.sh — always.** Claude prepares and hands off. A mid-race install on 2026-07-05 cost the operator a race's credits and its telemetry (guard: `49a0aa1`); read-only ssh is always fine. 4. **Git — trunk-based:** work on `main`; commit+push to `origin/main` **pre-authorized** for operator-validated changes, same session (done-bar = *pushed*, not committed — parked local work is how the 0.5.0 chords were lost). Origin gets out-of-band web edits → `git fetch` + `rebase`, **never force-push**. `garage` (private) never pushes to `origin`. Dossiers live in the gitignored private `dossiers/` clone — cite them freely, never commit them here. 5. **Identity/legal:** public artifacts under the **mercurious** pseudonym only; docs stay development/tuning-focused. Live `etk.conf` holds a real GitHub PAT — never republish it.

**The Sentry** (`01-etk-sentry.sh`, generated by install.sh STEP 6, `etk.service`, 2 s tick) is the state machine everything hangs off: seeds SHM at boot, pre-links the shader vault, re-injects Pitstop into the boot-volatile Tools menu (active tripwire), detects ignition via `pgrep -f "rpcs3-sa|AppRun.wrapped"`, resolves the game ID **before** spawning workers, and on shutdown fires the postmortem. ## 5. NOVEL MECHANISMS (technical detail, evidenced)

### 5.1 The full-stack GTK Anti-Lock (the flagship) A GPU wedge on stock ROCKNIX is a **dmesg-only soft-freeze**: a6xx fault → hangcheck → `rsx::thread` parks in a poll loop; no core, no fatal, process state S. The ledger proved the gap before the fix: **81% of 318 RECOVERY:Adreno rows had a kernel fault that never surfaced as `VK_ERROR_DEVICE_LOST`** — all 318 needed a human R3. The cure is layered across the owned stack, one layer per wedge class:

| # | Wedge class | Signature | Net | Layer | |---|---|---|---|---| | 1 | Query park — Turnip `get_query_pool_results` wait-poll | `00C5xxxx` | `TU_ETK_QUERY_SURVIVE` (query-survive) | driver | | 2 | Fence park — RPCS3 `vkGetFenceStatus` flip spin (**dominant**) | `00E5xxxx` | kernel `msm.context_keepalive` + `GTK_FENCE_FORCE_SIGNAL` | kernel + emulator | | 3 | FIFO-desync rsx-death ("RET without CALL" storm → thread dies) | 00E5 + RPCS3 fatal | `GTK_FIFO_RESYNC` (a watchdog can't ride the thread it guards) | emulator | | 4 | Post-rescue guest-state deadlock (game alive, frames dead) | double-digit rescues + fresh live_stat, stale mango CSV | `GTK_RSX_WATCHDOG` | emulator |

All default-ON since v0.7.0 with `=0` kill-switches (default-on idiom: `return !(v && *v == '0');` — `sync.cpp:583`, `RSXThread.cpp:953/1001`; Turnip `tu_query_pool.cc:604`). **Observability:** the kernel absorbs a hang invisibly, so `mango_bridge` counts dmesg `context_keepalive: surviving hang` deltas → HUD ANTI-LOCK gauge flashes `·«!»·` ~8 s then holds `·×NN·` (session rescue count); postmortem writes `KEEPALIVE_SURVIVE` + `rescues` (col 30) and reclassifies the row `SURVIVED:*`. **Evidence:** keepalive engaged on every live boss, N≥9 over two days incl. a 3,596 s session and GT5P races absorbing 7–8 rescues and *finishing*; v0.7.0 certification window: last ~9 sessions = 4 SURVIVED / 2 CLEAN / 3 RECOVERY / **zero frozen handhelds**, incl. a 32-min GT5P run that absorbed **13 rescues**. First fully-autonomous recovery (no human input): 2026-07-05, ledger row 1783262636. Operator verdict: "a screen blip and the DDU flashes, just like a real car… the race goes on."

### 5.2 Attributable tuning: tune_tag + ETK Dyno Every knob motion flows through an atomic write pair (§4) so `tools/etk_dyno.py` can group warm race sessions by (tune_tag, res, clk, pwr) and score by `perfect_pct` — with the discipline baked into code: bake runs excluded (`WARM_SHD=5`), ABORTED dropped, **no verdicts at N<3**, medians never means. Born from the near-crowning of `TU_DEBUG=sysmem`; delivered e.g. the **sddepth verdict** (2026-07-10 Suzuka dyno: only CLEANs of the stint, ~5 rescues/h vs 20–24/h — a 4–5× wedge-rate cut at equal fps) and the dial-era result (median duration +67%, time-to-crash +53%).

### 5.3 The shader vault + homologation Per-game vault (`vault/$CHIPSET/$ID/shaders`) live-symlinked over Mesa's cache (`ln -sfn` — plain `-sf` once built a self-loop that hung rsync at the kernel's 40-link limit). Staleness is keyed on the **Mesa VERSION-string fingerprint** (`vault/.last_mesa.hash`), because a driver swap recompiles the pipeline objects: `tools/vault_sweep.sh` prunes dead-epoch files past that boundary (first run reclaimed **174,954 files / 1.2 GB**; the GT6 vault was 97.6% corpse). Stage III lifts Mesa's silent 1 GB LRU cap to 10 G (`MESA_SHADER_CACHE_MAX_SIZE`) so the vault can't self-evict. Sharing (Private Paddock / pro-tuning) gates on a **homologation hash** — sha256 of the first 64 KB of the live `libvulkan_freedreno.so` — and ships bundles as pure data (the installer is the only code that runs).

### 5.4 The #11912 road-flicker fix (`GTK_REMAP0_ONE`) A 5-year-open upstream RPCS3 bug, root-caused **headlessly on the Mac** from the original reporter's 2023 RenderDoc captures: dim frames park the shadow sampler on a 1×1 A8R8G8B8 texture with zeroed `NV4097_SET_TEXTURE_CONTROL1`, which RPCS3 decodes as remap force-ZERO → black roads. The fork decodes remap 0x00 as ONE×4 (`0x55E4`). Field-validated flicker-free on Adreno 650/ROCKNIX, M1/MoltenVK, AMD/Windows, and the RPCSX Clanker port ("Eiger and Daytona 100% flicker-free"). Upstream comment posted; kd-11 pushback → a psl1ght hardware test is the live lane (`dossiers/HwTest_11912_Zfunc_Handoff_20260710.md`). Bonus catch: the published ffs-v4 patch had silently dropped the fix — found and repaired same day; the shipped binary was verified unaffected by extracting the actual ELF from the AppImage dwarfs payload.

### 5.5 Kernel-root fixes over workarounds (the audio precedent) The SM8250 ~1-in-4 silent-boot coin flip (ADSP's q6afe clock-vote error reply never woke the waiter; probe never retried; every LPASS device parked in `devices_deferred` forever) was first bridged by a userspace watchdog, then **fixed in the kernel** (rocknix-gtk Patch #2, `q6afe-vote-probe-race`: in-place vote retry, 250 ms/15 s bound) — and the watchdog was actively *retired* (install.sh STEP 6.57 tears it down). Ledger `snd` is card-presence-only now; `aud=` underrun telemetry is a separate live mechanism. This is the template: workaround → root fix → tear the workaround down.

### 5.6 The bog profiler (chord-triggered flame-graph forensics) `R1+DPAD-Down` mid-race → `perf record -F 199 -g` on the live emulator for `BOG_PROFILE_SECS` (default 30; 15 ≈ one track section), then **symbolized AT CAPTURE TIME** — the AppImage dwarfs mount dies with the session, so a later `perf script` resolves nothing. Meta sidecar self-labels the sample with `fps_end` from the perfstat SHM (bog vs perfect, no timeline join needed); DDU shows a `§~~~··` progress gauge during the window; host pulls with the cockpit's `grab_bog_sample.sh` ("grab sample"). **Evidence (one 33 K-sample capture, 2026-07-10):** named two pure-waste thieves — `sdl_pad_handler::update_connection` at 1 kHz = **~8% of all cycles** (→ Pad Poll Interval dial, golden default 1000→4000 µs, `fc0b0f2`) and the ZCULL query poll = **~5%** (→ Relaxed ZCULL Sync + Accurate ZCULL stats fields, `80125da`). ~14% ≈ a full core reclaimed from one sample.

### 5.7 GRID mode (big.LITTLE thread affinity) POWER-tab `grid` knob → `bin/grid_apply.sh` pins the hot set by comm-prefix (`rsx::thread`→prime, PPU→golds, SPU→golds, cellAudio→silvers; ~75 noise threads quarantined to silvers); thermal_d re-asserts every 60 s to catch late-spawned workers; attribution rides `pwr=race+gB`. **Evidence of honest falsification AND a win:** on GT5P pack it measurably cut contention (bog-CPU 63→51%) yet moved fps not at all → banked as "contention is INSIDE RPCS3"; on GT HD Eiger slush it relieved the serialized rsx chain — **min-fps 25→39, rsx 86%→50% of a core, a 10 s tail pinned at 60** (N=1/side; not crowned until N≥3). Standing: GRID-B on for GT HD, off for GT5P.

## 6. FORENSICS: TOOLS, METHOD, AND WHAT THEY'VE CAUGHT

### 6.1 The GPU-wedge capture chain (the crown jewel) 1. **Arm at IDLE, before launch** — `cat /sys/kernel/debug/dri/0/hangrd > cap.rd &`. The node blocks until the *next* wedge; a post-hoc cat captures 0 bytes (the first 00C51005 crack was lost exactly this way). 2. **Watch dmesg** — the dominant crash class is dmesg-ONLY (`a6xx_irq.*gpu fault`); core/log/ process watches all stay silent. `rocknix_spotter_loop.sh` runs three detectors: ADRENO (dmesg), SILENT (live_stat staleness + `emu_alive()` cmdline-walk — never pgrep; distinguishes graceful exits), NEW CORE / RPCS3 fatal. 3. **Finalize size-stable** — wait for the `.rd` to stop growing (~10 s of no growth), never a fixed timer: a 6 s kill truncated a capture to 211 MB undecodable; size-stable got 587 MB complete. 4. **`.faultinfo` sidecar** — dmesg `fence/status/ib1/ib2` written next to the capture; it aims the decode at the faulting draw instead of a 1,300-draw haystack. Manual captures without one are structurally decodable only. 5. **Repair, then decode** — `scripts/turnip/rd_inspect.py` (truncation/section check) → `rd_repair.py` (drops truncated tail, synthesizes `RD_CMDSTREAM_ADDR` from faultinfo ib1 sized to the FULL containing buffer — dmesg `ib1_size` is the *remaining* count) → `cffdump --once` in the turnip container (per-tile default = 400 MB of noise). Kernel **devcoredumps** (`.devcd`, auto-expire in 5 min!) decode with `crashdec`, not cffdump. 6. **Ledger join** — postmortem stamps `gpu_fault_status`/`gpu_fault_fence_hex` (cols 24–25) from the sidecar; `recovery.sh` binds the grim'd frozen frame as `crash_shot` (sway still composites the last frame after kernel recovery — the compositor is a separate GPU client).

Fault-code decode: `status` = A6XX_RBBM_STATUS — `00C5*` = query park, `00E5*` = fence park; rptr<wptr = CP stalled with work queued; zero SMMU faults = hang, not page fault.
